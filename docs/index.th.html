Technical reference

ChatGPTMCP Hybrid

ChatGPTMCP Hybrid รวมความสามารถสำหรับจัดการเครื่อง ช่วยวิเคราะห์งาน เรียกใช้ skills และใช้หน่วยความจำถาวรไว้หลัง interface เดียว โดย ChatGPT เป็นตัววางแผน และใช้ toolpy เรียก capability ที่จำเป็นระหว่างทำงาน

Hybrid surface

Legacy mode เปิด MCP tools แต่ละตัวให้ ChatGPT เรียกโดยตรง ส่วน Hybrid mode ซ่อน tools ระดับล่างไว้หลัง Python runtime และเปิดให้ ChatGPT เห็นเพียง toolpy กับ capability_registry ทำให้รายการ tools ที่โมเดลต้องเลือกมีขนาดเล็กลง แต่ยังเรียกความสามารถเดิมได้ครบเมื่อต้องใช้

Public toolหน้าที่
toolpyรัน Python ใน runtime ที่คงสถานะข้ามคำสั่งได้ ภายในแต่ละ cell สามารถดูรายการ capability เรียก tools ที่ได้รับอนุญาต ทำหลายขั้นตอนต่อเนื่อง และคืนผลลัพธ์แบบ structured data ได้
capability_registryดู metadata ของ capability ที่เรียกผ่าน toolpy แยกเป็น coding, think, skills และ memory โดยคำสั่งนี้จะไม่เรียก capability จริง

Runtime contract

allow_tools

capability แบบ read-only ใช้ได้เป็นค่าเริ่มต้น ส่วน capability ที่มีการแก้ไขระบบต้องระบุชื่อไว้ใน allow_tools ของคำขอ toolpy

session_id

กำหนดชื่อ session ของ IPython ตัวแปร imports และ helper ที่สร้างไว้จะใช้ต่อในคำสั่งถัดไปได้ จนกว่าจะ reset, ถูกล้างออก, worker restart หรือ session หมดเวลา

max_calls

จำกัดจำนวนครั้งที่แต่ละ cell เรียก MCP capability ภายใน

timeout_ms

กำหนดเวลารันสูงสุดของ cell หากเกินเวลาระบบจะปิด session เพื่อให้แน่ใจว่า process ที่เกี่ยวข้องถูกเก็บกวาด

max_output_bytes

จำกัดขนาด stdout, stderr, display output และ structured result ที่ส่งกลับ

catalog = await describe()
status = await tools.machine_status({})
result({"catalog": catalog, "status": status})

สิทธิ์ที่ต้องใช้: Hybrid mode ต้องเปิด --dangerously-open-machine เพราะ Python runtime ทำงานด้วยสิทธิ์เดียวกับ OS account ที่รัน MCP worker หากต้องการจำกัดการเข้าถึงให้อยู่เฉพาะ workspace ให้ใช้ tool surface แบบปกติ หรือรัน bridge ภายใน sandbox แยกต่างหาก

เพิ่ม capability provider

Hybrid mode สามารถเพิ่ม provider จาก directory ในเครื่อง แล้วให้ toolpy เรียกใช้งานได้ ปัจจุบัน CLI รองรับ Skill Hub, ThinkForge และ OurBook Memory

node dist/index.js \
  --dangerously-open-machine \
  --tool-surface hybrid \
  --skill-hub-dir D:\Projects\Github\chatgpt-skill-hub \
  --thinkforge-dir D:\Projects\Github\ThinkForge-MCP \
  --memory-dir D:\Projects\Github\ourbook

สถาปัตยกรรม

เมื่อใช้ Streamable HTTP คำขอจะเข้า MCP server โดยตรง ส่วนโหมด tunnel ผ่าน stdio จะวิ่งผ่าน apps/server/src/supervisor.ts ซึ่งรัน apps/server/src/index.ts แยกเป็น worker process หาก worker crash หรือทำงานเกินเวลาที่กำหนด supervisor สามารถ restart และ initialize worker ใหม่ได้ ภายใน worker ระบบจะตรวจชื่อ tool และ arguments ก่อนผ่าน policy, preconditions และ idempotency แล้วจึงเรียก handler ที่ทำงานกับเครื่องจริง

Architecture reference

Tunnel มีหน้าที่เป็นช่องทางรับส่งข้อมูลเท่านั้น ตัว MCP server ไม่ได้ผูกกับหน้า ChatGPT โดยเฉพาะ และสามารถใช้กับ MCP client อื่นที่รองรับ protocol เดียวกันได้

Tool surface

ใน Legacy mode server เปิด tools สำหรับจัดการเครื่องให้เรียกโดยตรง ส่วน Hybrid mode ยังใช้ capability ชุดเดิม แต่เรียกผ่าน toolpy แทน จึงไม่ต้องส่งรายการ tools ทั้งหมดให้ ChatGPT ทุกครั้ง

Inspect

machine_status, file reads, project snapshot, directory listing, file discovery, metadata, image inspection และ code search

Edit

เขียนไฟล์ แก้เฉพาะจุด อัปเดตแบบ transactional และใช้ patch

Run

รันคำสั่ง shell และจัดการ process ตั้งแต่ start, status, อ่าน output, wait, stop ไปจนถึงส่งข้อมูลผ่าน stdin

Git

จัดการ status, diff, log, show, branch, add, commit, verified commit, checkout และ push โดยไม่ประกอบคำสั่งผ่าน shell interpolation

System

ตรวจ process, port, environment, disk, network และข้อมูลเครื่อง โดยจำกัดขนาดผลลัพธ์และปิดบังข้อมูลสำคัญก่อนส่งกลับ

Workflow

มี verification gates, idempotency, audit, การส่งคำสั่งไปเครื่องอื่น และ OSINT แบบจำกัดขอบเขตเมื่อเปิดใช้งาน

Concurrency guard

เมื่ออ่านไฟล์ ระบบจะคืน SHA-256 มาด้วย ตอนเขียนสามารถส่งค่าเดิมกลับผ่าน expected_sha256 หากไฟล์ถูกแก้หลังจากที่อ่าน ระบบจะคืน PRECONDITION_FAILED แทนการเขียนทับไฟล์เวอร์ชันใหม่โดยไม่รู้ตัว

Stable failures

Codeความหมาย
INVALID_ARGUMENTinput ไม่ครบ รูปแบบไม่ถูกต้อง หรือค่าอยู่นอกขอบเขตที่รองรับ
PATH_DENIEDpath อยู่นอก workspace, symlink ชี้ออกนอกขอบเขต หรือสิทธิ์ของ OS ไม่อนุญาต
PRECONDITION_FAILEDไฟล์ถูกแก้หลังจากที่อ่านไปแล้ว
AMBIGUOUS_MATCH / NO_MATCHไม่สามารถระบุตำแหน่งที่ต้องแก้ข้อความได้อย่างแน่นอน
TIMEOUT / NETWORKคำสั่งหรือการเชื่อมต่อเครือข่ายไม่เสร็จภายในเงื่อนไขที่กำหนด

Safety model

Workspace-only mode จำกัดการอ่านเขียนไฟล์ การค้นหา working directory ของ shell และ patch ให้อยู่ภายใต้ --root เท่านั้น รวมถึงปฏิเสธ symlink หรือ junction ที่ชี้ออกนอกขอบเขต

Unrestricted mode เปิดด้วย --dangerously-open-machine ทำให้เข้าถึง absolute path และใช้ shell ได้ตามสิทธิ์ของ OS account ที่รัน server โดย Hybrid mode จำเป็นต้องใช้โหมดนี้เพราะมี Python runtime ที่คงสถานะข้ามคำสั่ง

ระบบนี้ออกแบบมาเป็น bridge สำหรับควบคุมเครื่อง ไม่ใช่ sandbox สำหรับผู้ใช้หลายคนที่ไม่ไว้ใจกัน ควรเชื่อมต่อเฉพาะ client และ tunnel ที่คุณยอมให้มีสิทธิ์ระดับเดียวกับ OS account ที่รัน server

Transport

Tunnel ใช้ stdio ที่มี supervisor คอยดูแล หรือเลือกใช้ Streamable HTTP ได้

node dist/index.js --http --http-port 8787 --root D:\Projects\Github

/healthz ใช้เช็กว่า process ยังทำงานอยู่ /readyz ใช้เช็กว่าระบบพร้อมรับงาน MCP requests อยู่ที่ /mcp ส่วนหน้า /ui อ่าน audit events ที่ปิดบังข้อมูลสำคัญแล้วจาก /ui/audit

หากเปิด HTTP ให้เข้าถึงจากภายนอกเครื่อง ต้องกำหนด bearer token และ token เดียวกันจะใช้ป้องกัน UI endpoints ด้วย

Operations

สำหรับ server หรือ watcher ควรรันผ่าน managed process runtime ข้อมูล process และ logs ที่จำกัดขนาดจะถูกเก็บไว้ใต้ .chatgpt-machine/ ดังนั้นแม้ MCP worker จะ restart ก็ยังกลับมาตรวจสถานะหรือสั่งหยุด process เดิมได้

chatgpt-local setup
chatgpt-local up
chatgpt-local status
chatgpt-local restart
chatgpt-local down
chatgpt-local doctor
chatgpt-local check
chatgpt-local config show
chatgpt-local version

ค่าของ local runtime เก็บใน .chatgpt-machine/config.json ซึ่งถูก ignore จาก Git ส่วน chatgpt-local use <path> ใช้กำหนด workspace ที่ต้องการใช้งาน

Multi-machine gateway

รายชื่อเครื่องที่อนุญาตให้เชื่อมต่อผ่าน Streamable HTTP เก็บใน .chatgpt-machine/machines.json ซึ่งถูก ignore จาก Git สามารถเลือกเครื่องด้วย id, name, hostname, alias, IP address หรือ host:port ได้ แต่ tool caller ไม่สามารถส่ง URL ใด ๆ เข้ามาเองได้
